# Tagmark v4.35

v4.34 기반 통합 업데이트. 단일 HTML 로컬 앱입니다.

## 설치 및 실행

`v4.35/index.html`을 브라우저에서 엽니다. 기존 v4.34와 **동일한 로컬 IndexedDB 식별자**를 사용하므로 같은 브라우저/도메인 환경에서는 이전 데이터가 표시될 수 있습니다. 브라우저에서 파일을 별도 경로로 열면 브라우저의 origin 정책에 따라 데이터가 분리될 수 있습니다. 작업 전 **DB 관리 → JSON 백업**을 권장합니다.

## 통합 개선 사항

- **표시 구성**: 북마크/Record 탭 상단의 표시 구성 버튼. 정보별 표시/숨기기, 라벨, 순서 설정을 Tab별로 저장. 내부의 `Field / Placement 구조 편집` 버튼은 v4.34의 필드/하위 영역 구성 도구를 엽니다.
- **입력 구성**: 표시 위치와 별도로 입력 순서와 입력 방식 설정. 동일 Input ID는 한 번만 나타나며, Tab 간 순서와 방법을 독립적으로 설정합니다. 기존 Tag, Record, Relation 입력기 함수는 재사용합니다.
- **색상 규칙**: 선택한 정보 항목의 값에 따라 Record/북마크 카드의 색상 표시. Male/Female/Both 기본값을 포함하며 임의의 선택값과 색상 추가 가능. Record 내용 상속 및 카드 강조 범위를 선택합니다.
- **기존 값 보존**: 기존 `values[inputId]`, Record 카드, 태그, JSON 백업 구조 보존. 입력기를 숨겨도 값이 삭제되지 않습니다.
- **Undo/Redo**: 새로운 구성 저장은 기존 트랜잭션 경로를 통해 기록합니다.

## 주요 주의사항

- Tab별 표시 순서 정렬은 **필드 단위**로 적용됩니다. 동일 Field에 여러 Placement가 있는 경우 해당 필드 내부의 정렬은 v4.34 구조 편집에서 관리합니다.
- Field/Placement의 실제 생성과 삭제는 여전히 공유 Schema에 적용됩니다. Tab별 독립화는 기본 표시 순서·표시 여부·표시명에 적용되며, 공유 Schema의 전체 분리 기능은 포함하지 않습니다.
- 색상 상속은 현재 Tab 카드의 텍스트 및 테두리 표시를 대상으로 합니다. 개별 Placement에 지정한 스타일은 재정의될 수 있습니다. 조건식은 현재 **문자열과 정확히 일치**하는 경우를 지원합니다.
- 브라우저의 실제 인터랙션 회귀 테스트는 수행되지 않았습니다. JavaScript 구문 검사와 압축 무결성 검사는 수행했습니다.
